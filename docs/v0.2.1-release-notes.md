# Tupperware v0.2.1 Release Notes

**Provision from Claude.** A stdio MCP server that lets an AI client — Claude Code or Claude Desktop — list containers and clone the golden template directly, with no copy-pasting of `tupperware-new` commands.

## What's new

### `mcp/` — a stdio MCP server

A [FastMCP](https://modelcontextprotocol.io) server that wraps the existing provisioning path. Three tools:

- **`tupperware_host_status`** (read) — container/VM counts, tailnet peer count, next free VMID, storage backends, template readiness
- **`tupperware_list_containers`** (read) — LXC inventory
- **`tupperware_provision`** (write) — clone the golden template + join tailnet. **`dry_run=True` by default**: it resolves and returns the plan (target VMID, storage, sizing) without creating anything; call again with `dry_run=False` to execute. No destroy tool, by design.

### Two read-only JSON routes on the web app

`webui/app.py` gains `GET /api/status` and `GET /api/containers` — JSON versions of the dashboard metrics and inventory that the MCP (and any scripted client) reads. Purely additive; the HTML UI is unchanged.

### `mcp/check_mcp.py` — handshake self-test

Runs a real MCP handshake against the server and prints the tool list, independent of any client. Use it to prove the server works before suspecting client config.

## Design

The MCP is an **HTTP client only**. It never runs `pct` or SSH — every action goes through the same endpoints the web UI uses (`/api/status`, `/api/containers`, `/clone-stream`), so it holds no direct root power on the host. See [docs/mcp.md](mcp.md).

## Using it

Claude Code:

```bash
cd mcp && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
claude mcp add tupperware -s user -- \
  "$PWD/.venv/bin/python" "$PWD/tupperware_mcp.py"
```

Claude Desktop: add the same command/args under `mcpServers` in `claude_desktop_config.json`, then fully quit and restart Desktop. Full steps in [mcp/README.md](../mcp/README.md).

## Prerequisites

- The web app must be running with the v0.2.1 `/api/status` + `/api/containers` routes (redeploy `webui/app.py` and restart the service).
- Python 3.10+ on the client machine (for the venv).
- Network reachability from the client to the web app (LAN, or tailnet IP / MagicDNS name).

## Upgrading from v0.2.0

Redeploy the web app so the new routes are live:

```bash
scp webui/app.py root@<prox-host>:/opt/tupperware/app.py
ssh root@<prox-host> systemctl restart tupperware
```

Then install + register the MCP per [mcp/README.md](../mcp/README.md).

## Security notes

- `tupperware_provision` defaults to dry-run; there is no destroy tool.
- The new `/api/status` and `/api/containers` routes are read-only and, like the rest of the web UI, unauthenticated — they rely on the same tailnet-only access model. Don't expose the web app to untrusted networks.
- In Claude Desktop, every tool call requires per-action approval, so a real provision is two deliberate approvals (plan, then execute).

## Known limitations

- No live progress streaming to the client — `tupperware_provision` returns the full console output once the clone finishes.
- Provisioning + reads only; no destroy or transfer tools exposed over MCP yet.
- Success detection relies on the web app's `/clone-stream` output format (`[OK]` / `[!]`).
