# Tupperware v0.2.8 Release Notes

**Disk health.** SMART data for the host's physical disks at `GET /api/disks`,
and through a new `tupperware_disk_health` MCP tool.

Per drive: model, capacity, power-on hours, wear, lifetime writes, reallocated
sectors, temperature, available spare, and the drive's own PASS/FAIL verdict.
NVMe and SATA both supported, collected in parallel and cached for
`TUPPERWARE_DISK_CACHE_TTL` seconds (default 600) so a slow `smartctl` never
blocks a request.

## Wear is reported honestly

NVMe exposes `percentage_used` in a standard field, so wear is reliable there.

SATA vendors reuse attribute IDs for unrelated things — ID 233 is
`Media_Wearout_Indicator` on Intel but `NAND_GiB_Written` on SanDisk, a byte
counter that decodes as "0% worn" forever. Matching on ID alone silently
reports healthy drives as new and worn drives as new too. Tupperware accepts a
wear attribute only when its name also looks like a life gauge, and reports
`used_pct: null` rather than guessing.

For those drives, `drive_writes` (lifetime writes as full-capacity writes) is
the wear signal: compare it against the model's rated endurance.

## Requirements

`smartctl` must be installed on the host. Where it is missing, the route still
answers and the affected drive carries an `error` field.
