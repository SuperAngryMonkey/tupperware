# Tupperware v0.2.7 Release Notes

**Per-host storage configuration.** Two new admin-selectable environment variables, for hosts whose storage layout differs from the default assumption.

## `TUPPERWARE_DEFAULT_STORAGE`

Selects the default storage backend. Previously hardcoded to `local-lvm`, which does not exist on ZFS-backed nodes — those hosts had no working default at all.

```
Environment=TUPPERWARE_DEFAULT_STORAGE=local-zfs
```

## `TUPPERWARE_HIDE_STORAGES`

Comma-separated list of storage names to keep out of the provisioning picker — useful when a host has scratch or non-redundant disks that should never receive a container.

```
Environment=TUPPERWARE_HIDE_STORAGES=dump,scratch
```

The default storage is never hidden, even if it appears in the list, so a host can never be left with no valid provisioning target. Unset (the default) shows every backend, as before.

## Also fixed

- `tupperware-export-template` failed on Proxmox 9: `vzdump` rejects `--notes-template` unless `--storage` is given, which conflicts with `--dumpdir`. The flag is dropped; exports work on PVE 8 and 9.

## Files changed

- `webui/app.py` — `TUPPERWARE_DEFAULT_STORAGE`, `TUPPERWARE_HIDE_STORAGES`
- `scripts/tupperware-export-template.sh` — PVE 9 compatibility
