# Tupperware v0.2.6 Release Notes

**Admin-selectable source scoping.** New `TUPPERWARE_ALLOW_SOURCES` environment variable: a comma-separated CIDR list. When set, every request from a source address outside the list is refused with `403` before authentication runs. Unset (the default) means no restriction.

This is a per-host choice by design: it only really applies to hosts exposed to the internet. Hosts behind a perimeter firewall can leave it unset and lose nothing.

## Enabling

```bash
systemctl edit tupperware
# [Service]
# Environment=TUPPERWARE_ALLOW_SOURCES=127.0.0.0/8,10.0.0.0/24,100.64.0.0/10
systemctl restart tupperware
```

A malformed CIDR fails at startup (visible in `systemctl status`) rather than silently running unrestricted.

## Layering

Three independent, individually optional layers now exist: `TUPPERWARE_ALLOW_SOURCES` (request source), `TUPPERWARE_BIND` (listen interface, v0.2.5), and HTTP Basic Auth via the auth file (v0.2.2). Use whichever combination the host's exposure warrants.
